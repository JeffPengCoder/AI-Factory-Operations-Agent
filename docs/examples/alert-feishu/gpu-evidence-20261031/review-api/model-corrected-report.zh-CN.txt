## 二、DCGM 取证与隔离引擎勘正

### 2.1 隔离 DCGM 引擎的正确理解

**先前的错误**: 声称 `--denylist-modules 1,2,3,4,5,6,7,8,9` "禁用所有硬件模块"、"隔离引擎无硬件轮询"。

**更正**: `--denylist-modules 1,2,3,4,5,6,7,8,9` 仅禁用辅助模块（如 NVSwitch、NVLink、PCIe 统计等），模块 0（核心 GPU 模块）仍然包含在内。隔离引擎仍然会枚举 GPU、读取 NVML 状态。隔离的本质是：

- 启动了一个**新的子进程** `nv-hostengine`，通过 `--domain-socket /var/tmp/mosaic-gpu-rca-20261031t121240z-attempt3/engine.sock` 监听私有 Unix socket
- 拥有独立的缓存层，注入通过 `dcgmi test --inject` 修改缓存
- 进程被**刻意终止**（`privateEngineAlreadyStopped: true`），与生产 DCGM 引擎无共享缓存
- 目录隔离在 `mosaic-gpu-rca-20261031t121240z-attempt3` 子目录

隔离是**新的私有 Unix 套接字、不同子进程/缓存和受限目录**，不是无硬件进程。

### 2.2 注入偏移量 --offset 60 的语义

**先前的错误**: 将 `--offset 60` 解释为"注入 TTL 60 秒"或"夹具生命周期"。

**更正**: `--offset 60` 表示注入的样本时间戳被设置为**60 秒未来时间**，用于测试时间窗口对齐和重放兼容性。注入本身没有 TTL 或自动过期。隔离引擎被捕获后**被有意终止**，但 replay Pod（busybox httpd）继续运行直至操作员清理，没有自销毁机制。

## 十、根因分析

### 告警根因

**本告警为受控的 DCGM 缓存快照重放测试信号，非物理 GPU 故障。**

Jeff Peng 发起的 GPU 遥测仿真实验：
1. 在隔离 DCGM 引擎（私有 Unix socket，子进程，受限目录）中启动 `nv-hostengine`
2. 通过 `dcgmi test --inject` 注入 Xid 95（字段 230）和 ECC 值 1（字段 311、313），时间戳偏移 60 秒
3. 采集隔离引擎快照后终止引擎进程
4. replay Pod（busybox httpd）通过 `/metrics` 端点持续暴露缓存中的 Xid 95 值
5. Prometheus 以 60 秒步长抓取，触发告警规则

### 证据链一致性

| 证据源 | 是否有 Xid 95 / ECC 错误 | 来源/备注 |
|---|---|---|
| 隔离 DCGM 缓存（注入目标） | ✅ Xid 95, EDVTL=1, EDATL=1 | `dcgmi dmon` 通过隔离 socket 读取 |
| 生产 DCGM（端口 5555） | ❌ 全零 | `dcgmi dmon` 直接读取硬件 |
| NVML 快照（注入前后） | ❌ 全部 0，未变 | `nvidia-smi` 采集 |
| `DCGM_FI_DEV_UNCORRECTABLE_REMAPPED_ROWS{Hostname="target-node-1",gpu="0"}` | 值 0（存在系列） | 生产 DCGM exporter |
| `DCGM_FI_DEV_CORRECTABLE_REMAPPED_ROWS{Hostname="target-node-1",gpu="0"}` | 值 0（存在系列） | 生产 DCGM exporter |
| `DCGM_FI_DEV_ROW_REMAP_FAILURE{Hostname="target-node-1",gpu="0"}` | 值 0（存在系列） | 生产 DCGM exporter |
| `dcgm_health_active_events{instance="target-node-1.example.invalid:2112"}` | 值 0（ConnectivityFailure） | 生产 DCGM 健康监控 |
| 内核 dmesg（NVRM/Xid） | ❌ 无匹配行 | 采集快照 |

全部独立硬件证据源与注入的隔离 DCGM 缓存不一致，符合知识库 P2 规定的"仿真遥测、无活硬件故障证据"判定。

### 置信度

- **本轮告警由缓存快照重放导致的置信度**: 高
- **物理 GPU 故障的证据**: 不足
- **RMA 适用性**: 不适用
- **此判定不证明 GPU 永远不会出现硬件故障**
